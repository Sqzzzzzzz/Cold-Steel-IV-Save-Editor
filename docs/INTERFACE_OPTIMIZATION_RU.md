# Interface Improved — технический отчёт

Исторический отчёт этапа оптимизации 0.1.2-preview. Текущие релизные проверки: [VALIDATION.md](VALIDATION.md).

Дата: **5 ноября 2026**. Версия интерфейса: **0.1.2-preview**.
База сравнения: `acfe30206440e197a6dcb1cb7d739ec845942549`.
Изменения и сборка находятся локально; отправки в GitHub не было.

## Выполненные изменения

- `QTableWidget` сохранён. Снимки отображаемых строк позволяют пропускать запись неизменившихся данных; существующие ячейки используются повторно. При поиске или сортировке каталога неизменившийся инвентарь не пересоздаётся.
- Для каждой таблицы сохранены собственная сортировка, выделение по ID и текущая запись. Обработан и внешний вызов `sortItems()`, который сбрасывает снимок расположения строк.
- Категории считаются одним проходом через `Counter`. Узлы обоих деревьев, их иконки и неизменившиеся подписи используются повторно.
- Видимый каталог, локализованные названия и текст поиска кэшируются в окне. Кэши сбрасываются при замене каталога через `EditorCore.rebuild_catalog()`, замене английских записей, смене языка и явном обновлении каталога. Приоритет пользовательских изображений сохранён.
- Один `QIcon` используется для одного пути изображения. Раздельные сведения об источнике и проверенности каждого предмета сохранены. Вместо 1 793 уникальных объектов иконок в измеренном сценарии осталось **72**; сами изображения не менялись.
- Поисковая строка нормализуется один раз на проход. Описание вычисляется только при необходимости и затем используется из кэша. Задержка ввода **140 мс** сохранена.
- У взаимоисключающих фильтров убрано повторное обновление таблиц.
- Рабочий поток сканирования получает копию строки пути к игре вместо обращения к изменяемым настройкам контроллера. Для рабочего метода и принимающих GUI-методов явно указаны `@Slot`. `QPixmap` и виджеты по-прежнему создаются в GUI-потоке.

Изменений формата сохранения, правил редактирования, файловых проверок, тем, делегатов отрисовки или зависимостей нет. Переход на другую модель таблицы не потребовался для полученного ускорения.

## Подтверждённые ошибки

1. **Исключение при обновлении могло оставить таблицу без сигналов и перерисовки.** В исходной версии воспроизведён отказ `_icon()` с `RuntimeError`: после него `signalsBlocked()` оставался `True`, а `updatesEnabled()` — `False`. Теперь `QSignalBlocker` и `finally` восстанавливают прежние состояния. Незавершённый снимок строк удаляется; повторное обновление восстанавливает данные.
2. **Переключение взаимоисключающих фильтров запускало два полных обновления.** Обновление теперь одно, состояния флажков и пункта меню синхронизированы. Это проверяет отдельный тест.

Новых подтверждённых ошибок локализации, игровых данных или потоков при проверке не обнаружено. Изменения потоков являются уточнением границ доступа, а не заявлением о ранее воспроизведённом сбое потока.

## Измерения до и после

Среда: Windows 11, Python 3.14.4, PySide6 6.11.3; стиль **Fusion**, как в штатном `main()`.
Одинаковая локальная копия каталогов: **1 792 видимых предмета**, искусственный инвентарь из **900 записей**. SHA-256 входных каталогов во всех прогонах одинаковый.

Для каждого варианта выполнены три запуска отдельного процесса. В таблице приведена медиана трёх результатов; каждый результат операции — медиана семи повторений. Прокрутка измерялась по 40 перемещениям. Время операций включает обработку событий и отрисовку, но исключает намеренную задержку поиска 140 мс.

| Операция | До | После | Изменение |
|---|---:|---:|---:|
| Подготовка данных, создание и первый показ окна | 1 689 мс | 1 340 мс | −21% |
| Обновление таблиц без изменений | 64,13 мс | 13,91 мс | **4,6× быстрее** |
| Обновление категорий | 38,41 мс | 6,82 мс | **5,6× быстрее** |
| Поиск / сброс поиска | 47,60 мс | 26,31 мс | **1,8× быстрее** |
| Сортировка названий | 63,35 мс | 34,79 мс | **1,8× быстрее** |
| Переключение категории | 45,73 мс | 23,26 мс | **2,0× быстрее** |
| Обновление карточки предмета | 8,37 мс | 8,60 мс | Существенного улучшения нет |
| Шаг прокрутки с отрисовкой | 6,68 мс | 6,45 мс | Разница мала; ускорение не утверждается |
| Память процесса после первого показа: private | 133,49 MiB | 123,71 MiB | −7,3% |
| Память процесса после первого показа: working set | 178,10 MiB | 168,86 MiB | −5,2% |

«Первый показ» включает чтение JSON, создание `DemoCore` и подготовку искусственного инвентаря; это не замер холодного старта упакованного EXE с диска. Показатели памяти — снимки процесса, не пиковая память. Это локальные результаты указанного сценария, а не обещание одинаковых чисел на любом компьютере.

## Стабильность, файлы и локализация

- Полный набор: **94 passed, 1 skipped**, 7,63 с. Добавлено **10** регрессионных тестов.
- Проверены поиск, фильтры, независимая сортировка, множественное выделение, текущая запись, незавершённое количество, отметки правок после undo, обновление кэшей, повторное использование иконок и восстановление после исключения.
- Проверены три последовательных фоновых сканирования: чтение выполняется вне GUI-потока, применение результата — в GUI-потоке; таймер интерфейса продолжает работать, завершённые `QThread` удаляются.
- Выполнено чтение установленной игры через реальное окно: **14 таблиц, 1 825 записей**, **124 проверки иконок мастер-кварцев RU/EN**. В английских отображаемых названиях и описаниях кириллицы нет. Искусственный файл сохранения и его данные в памяти не изменились от сканирования и переключения языка.
- Самопроверки исходной программы и EXE прошли: CRC, атомарные изменения, сохранность данных вне инвентаря, Unicode-пути, сохранение копии, запрет перезаписи копии, резервная копия, отмена, защита CSV и проверка всех **146** исходных PNG.
- В стресс-сценарии выполнены **500 циклов** поиска и сортировки. С 50-го по 500-й цикл: **351 дочерний QObject**, private memory **127,06 MiB** во всех контрольных точках. Признаков нарастающего удержания ресурсов в этом сценарии нет.
- Ручной цикл измерительного инструмента доставляет `DeferredDelete`, как обычный цикл событий: иначе анимации кнопки очистки поиска создавали ложное впечатление накопления объектов.
- В штатных Fusion-прогонах и стресс-прогоне предупреждений Qt не зафиксировано. В диагностике с нативным стилем Windows одинаковое до и после предупреждение `QFont::setPointSize ... (-1)` исчезает при использовании штатного Fusion; код приложения его не подавляет.

## Проверка внешнего вида и независимый review

Отдельный агент `independent_ui_review` проверил изменения, кэши, исключения, владение объектами Qt, потоки, сохранение выделения, новые тесты и методику измерений. Подтверждённых нерешённых замечаний нет.

Агент выполнил **18 сравнительных сценариев** исходного и изменённого окна: тексты таблиц, подсказки, роли изменений, выделение, карточка и количество совпали после действий. Сортировка с равными ключами также проверена.

**Все шесть итоговых пар скриншотов RU/EN 1536×864 совпали по RGB-пикселям.** Перед захватом курсор установлен в одинаковое нейтральное место, завершена штатная анимация очистки поиска. Агент независимо подтвердил сравнение. Цвета, шрифты, геометрия, стили, фон и файлы иконок намеренно не менялись.

## Ограничения

Один тест пропущен из-за отсутствия `CS4_REFERENCE_SAVE`. Загрузка изменённого сохранения самой игрой по-прежнему не проверена. Сохранённое оформление подтверждено сравнением описанных состояний и исходников; все возможные DPI, разрешения и многочасовая работа не проверялись. Стресс-прогон на 500 циклов не является доказательством отсутствия любых возможных утечек.

Машиночитаемые результаты: [ui-optimization.json](validation/ui-optimization.json).

Пример повторного измерения на подготовленной локальной копии каталогов:

```powershell
.\.qt-preview-venv\Scripts\python.exe tools\benchmark_ui.py --catalog-dir checks\ui-performance\catalog --output checks\ui-performance\repeat.json
```

Для сравнения с другой версией передайте `--source-root`; для стресс-проверки — `--cycles 500`. Без `--catalog-dir` используется небольшой искусственный демонстрационный каталог.
